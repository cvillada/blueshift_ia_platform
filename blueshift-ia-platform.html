📋 Visão Geral do Projeto

A BlueShift IA Platform é uma plataforma de inteligência artificial que eu estou desenvolvendo para ser instalada dentro da infraestrutura do cliente — datacenter, servidor dedicado ou nuvem privada.

A plataforma é genérica e prática em qualquer segmento de negócio — não é atrelada a um setor específico. Os agentes e skills são parametrizáveis por área da empresa (vendas, suporte, financeiro, RH, operações), e os modelos são ajustados com os dados do cliente.

Diferente de SaaS onde os dados saem da empresa, aqui tudo fica dentro do ambiente do cliente: dados, modelos, agentes, memória dos usuários, histórico. Os modelos sao configurados pelo cliente (locais ou externos), e rodam dentro da infraestrutura contratada.

Modelo híbrido: a plataforma também consegue acessar modelos externos (OpenAI, Claude, Gemini) para tarefas específicas. O controle é do cliente — dados sensíveis ficam nos modelos locais, tarefas não-críticas podem usar externo, com auditoria total.

Cada instância é isolada por cliente. Cada usuário tem memória persistente individual. O acesso é controlado por usuário e sistema via MCP (Model Context Protocol) ou API — cada um vê e faz só o que tem permissão.

⚙️ Como Funciona — O Modelo

1. Instalação no Cliente

  • Subimos a plataforma num servidor do cliente (bare metal, VM, nuvem privada)
  • Tudo em containers Docker orquestrados
  • Zero dependência de serviços externos
  • SSL, domínio e proxy reverso sao configurados pelo cliente conforme a politica de TI
  • Tempo de setup: 1-2 dias

2. Modelos de IA Híbridos (cadastrados pelo cliente)

  • Não embutidos: o cliente cadastra seus próprios endpoints OpenAI-compatible no Portal (tela Modelos IA)
  • Local: vLLM / LM Studio / Ollama na infra do cliente — dados não saem
  • Externo opcional: OpenAI / Claude / DeepSeek / Gemini via api_key, sob controle do cliente
  • Suporte a Llama, Qwen, DeepSeek, Mistral (7B-70B), quantizados (4-bit) se a GPU exigir
  • Fine-tuning: serviço opcional contratado — treinamos com os dados do cliente e entregamos o modelo para rodar local

3. Agentes de IA por Área

  • Assistentes pré-configurados: vendas, suporte, RH, financeiro, operações
  • Cada agente acessa só os dados que precisa ver
  • Workflows automáticos com gatilhos e alertas
  • Painéis e relatórios sem precisar de TI
  • Tudo: perguntas em português, respostas com dados reais

4. Portal e Suporte (core)

  • Portal do cliente: gerenciar, cadastrar e monitorar tudo num lugar
  • Admin cadastra usuários, áreas, agentes e conectores
  • Monitoramento de uso, saúde dos modelos e dos conectores MCP
  • Novos modelos fine-tuned liberados periodicamente
  • Atualização via tela Atualizações (git pull + rebuild, dados preservados)
  • Suporte técnico incluso
  • Modelo: licença anual por empresa (não por token)

5. Memória Persistente por Usuário

  • Cada usuário logado tem memória individual — o assistente lembra do histórico
  • Preferências, contexto de conversas e decisões anteriores persistidas
  • A memória de um usuário nunca interfere na de outro
  • Usuário pode consultar, limpar ou exportar a própria memória
  • Persistência: banco vetorial local (dentro do cliente)

6. Controle de Acesso via MCP / API

  • Autenticação por usuário (login + senha / SSO) e por sistema (chave MCP ou API key)
  • MCP (Model Context Protocol): ferramentas externas se conectam com escopo restrito
  • Cada permissão define: o que vê (dados), o que faz (agentes), o que configura (admin)
  • Sistemas internos (ERP, CRM) acessam a IA via API com rate limit e escopo próprio
  • Hierarquia: Admin > Gestor > Usuário > Sistema (MCP/API)
🔗 Fluxo de Ponta a Ponta (API → Agente → Resposta)

Tudo interligado e operacional — 100% on-premise

  • 1. Requisição: sistema externo (site, CRM, Zapier) ou usuário chama POST /api/v1/agente com o token do canal (Bearer) + {pergunta}. Autenticação via API key do canal.
  • 2. Orquestrador (Agent Factory): o agente monta o contexto dinâmico = Memória do usuário (RAG, banco vetorial local TF-IDF) + Base de Conhecimento do cliente + dados de conectores MCP reais (ERP/CRM/RH) + Skills da área.
  • 3. Modelo de IA: envia ao endpoint OpenAI-compatible cadastrado pelo cliente — local (vLLM / LM Studio / Ollama) ou externo (OpenAI / Claude / DeepSeek / Gemini) via api_key opcional.
  • 4. Tratamento de falha / Fallback: se o modelo principal não responde, o agente troca automaticamente para o modelo de fallback cadastrado e entrega a resposta; toda tentativa é registrada na Auditoria (LGPD).
  • 5. Log: toda chamada é auditada — quem perguntou, qual agente, qual ferramenta MCP, IP e resultado.
  • 6. Retorno: JSON com {ok, resposta, agente, modelo, contexto, ferramentas, erro}; se o canal tiver webhook de saída, a resposta também é POSTada nessa URL.

💬 Perguntas que o cliente vai fazer

"Precisa ter GPU? Que placa?"

Sim, pra rodar os modelos localmente. Uma RTX 4090 (24GB) roda modelos de 7B-14B. Uma A100 roda 70B. Se o cliente não tiver, a gente ajuda a contratar um servidor dedicado com GPU (Hetzner, OVH, AWS) que funciona como se fosse on-premise.

"E se a internet cair?"

A plataforma continua rodando normalmente — ela é local. Tá tudo dentro do cliente. Só perde acesso remoto, mas a operação local não para.

"Como atualiza os modelos?"

Pela tela de Atualizações do portal: a plataforma puxa a versão nova do repositório (tag) e recria os containers — dados preservados, operação não para. O cliente autoriza e acompanha pelo log. Zero risco de vazamento.

"O que é MCP (Model Context Protocol)?"

MCP é um protocolo aberto (criado pela Anthropic) que permite sistemas externos se conectarem à plataforma de IA de forma padronizada e segura. Em vez de cada sistema ter que criar uma integração customizada, o MCP define uma linguagem comum: o sistema diz qual ferramenta quer usar, a IA autoriza ou não com base nas permissões, e a resposta volta num formato padrão. É como um USB pra IA — qualquer sistema compatível se conecta sem esforço.

"Cada usuário tem a própria memória? Não se mistura?"

Isolamento total. A memória de cada usuário fica num banco vetorial separado por ID de usuário. O João nunca vê o que a Maria perguntou. O assistente de vendas lembra do pipeline do time de vendas, mas não acessa dados de RH. Tudo controlado por workspace + permissão — e tudo dentro do servidor do cliente.

"E se a empresa crescer?"

Sobe mais containers no mesmo servidor ou adiciona mais GPUs. A arquitetura é horizontal — escala conforme a demanda. Sem migração, sem recomeço.

"Consegue integrar com nossos sistemas (ERP, CRM)?"

Sim. A plataforma tem conectores pra SQL, APIs REST, arquivos, e sistemas legados. Como tudo roda dentro da rede do cliente, a integração é direta e segura.
